# Link Provider

Replaces the plain `<a>` that Octave's link-rendering components use with your router's link component, through React context. Renders no element of its own.

## When to use

- Wrap your app once, near the root, when it uses a router with its own link component — Next.js, React Router or similar — so Octave's links get client-side navigation and prefetching.
- Leave it out on sites without a client-side router. Without a provider, every link is a standard `<a>`.
- It only changes the links Octave renders — `Button` with an `href`, and `SiteHeader` — plus your own components that read it with `useLinkContext`. Other links on the page are untouched.

## Import

```tsx
import { LinkProvider } from '@troychaplin/octave-design-system';
```

## Basic usage

`component` takes any component that accepts the props of an `<a>`, `href` included.

```tsx
import type { ComponentPropsWithoutRef } from 'react';
import { Link } from 'react-router-dom';
import { LinkProvider } from '@troychaplin/octave-design-system';

// React Router's Link takes `to`, so map `href` onto it
const RouterLink = ({ href = '', ...props }: ComponentPropsWithoutRef<'a'>) => (
    <Link to={href} {...props} />
);

<LinkProvider component={RouterLink}>
    <App />
</LinkProvider>;
```

Define the wrapper outside your components, as above. A component created inline on every render would remount every link each time.

### Next.js App Router

`LinkProvider` is a Client Component, and a Server Component can't pass a function such as Next.js's `Link` to one. Put the provider in a client file of its own:

```tsx
// app/providers.tsx
'use client';

import Link from 'next/link';
import { LinkProvider } from '@troychaplin/octave-design-system';

export function Providers({ children }: { children: React.ReactNode }) {
    return <LinkProvider component={Link}>{children}</LinkProvider>;
}
```

Then wrap the root layout's children in `<Providers>`. The [Next.js guide](?path=/docs/overview-getting-started-next-js--docs) has the full setup, including the Pages Router.

### Your own components

To give a component of your own the same behaviour, read the link component with `useLinkContext` instead of hardcoding `<a>`. It's exported from the `LinkProvider` entry point, not the package root. The hook reads React context, so in the Next.js App Router the file needs a `'use client'` directive, as Octave's own link components have:

```tsx
'use client';

import { useLinkContext } from '@troychaplin/octave-design-system/LinkProvider';

export const ProjectCard = ({ href, children }) => {
    const LinkComponent = useLinkContext();

    return (
        <article>
            <LinkComponent href={href}>{children}</LinkComponent>
        </article>
    );
};
```

Without a provider above it, `useLinkContext` returns a component that renders a plain `<a>`.

## Props

| Prop        | Type            | Description                                         |
| ----------- | --------------- | --------------------------------------------------- |
| `component` | `LinkComponent` | Required — the component to render instead of `<a>` |
| `children`  | `ReactNode`     | Required — the part of the tree that uses it        |

`LinkComponent` is `ComponentType<ComponentProps<'a'>>`: any component that takes the props of an `<a>`.

## CSS classes

None. `LinkProvider` renders no element.

## Design tokens

None.

## Accessibility

- `LinkProvider` renders nothing itself, so it doesn't change the page's structure or the accessibility tree.
- The component you pass is responsible for the link's accessibility. It should render a real `<a>` and pass on every prop it receives: `Button` passes its classes and any `aria-*` attributes this way, and `SiteHeader` passes `rel="home"` on its title link.
