# About Octave

**One set of design tokens. A React library and a WordPress theme that never drift apart.**

Octave is a token-first component library for React and Next.js — and, from that same source of
truth, a complete WordPress block theme, hybrid theme, and block-plugin styling layer. Define a
color, a type step, or a spacing value once, and every surface picks it up.

Most design systems make you choose an ecosystem. Octave compiles one token definition into both,
so a React app and the WordPress Site Editor render the same design language because they read the
same values — not because someone remembered to update a second stylesheet.

## Why Octave

- **One source of truth, two ecosystems.** Tokens live in `c2b.config.json` and compile to CSS
  custom properties, SCSS variables, base element styles, and a WordPress `theme.json` with matching
  editor styles.
- **Fluid by default.** All 16 type steps are `clamp()` values that scale with the viewport, and the
  spacing scale goes fluid from `small` upward — responsive typography without a stack of breakpoints.
- **No runtime, no lock-in.** Plain SCSS and CSS custom properties. No Tailwind, no CSS-in-JS, no
  provider to wrap your tree in. Per-component CSS is exported individually, so a WordPress block can
  ship only the styles it actually uses.
- **Accessibility is a build failure.** Every story runs through axe at the `error` threshold on
  every pull request and on pre-push. A violation blocks the merge — it isn't a warning someone
  triages later.
- **Deliberately small.** Budgeted at 25 kB for the JS bundle and 7 kB for the stylesheet, enforced
  on every build.

## What's here today

Octave is **early-stage and being rebuilt**. The token pipeline, build system, and accessibility
tooling work; the component catalogue is small and growing. See
[Getting Started](?path=/docs/overview-getting-started-overview--docs) for installation.

### Design tokens

A single set of tokens drives both the React library and the WordPress block theme output. Tokens
are defined in `c2b.config.json` and generated by
[`@troychaplin/component2block`](https://www.npmjs.com/package/@troychaplin/component2block) into
CSS custom properties (`--octave--*`), SCSS variables, base element styles, and `theme.json`.

- **Colors** — `accent-primary` and `accent-secondary`, an 11-step neutral ramp (`neutral-50`
  through `neutral-950`), semantic states (info, success, warning, error), and brand colors for
  seven social platforms
- **Typography** — three typefaces (Inter Tight, Source Serif 4, JetBrains Mono), 16 fluid size
  steps, nine weights, three line heights
- **Spacing** — a 12-step scale from `3-x-small` to `5-x-large`, fluid from `small` upward
- **Effects** — five shadow presets (natural, deep, sharp, outlined, crisp), five border radii, gradients
- **Layout** — content width, wide width, small width, and full-bleed

Browse the live token reference under **Stylebook** in the sidebar.

### Components

The catalogue is being rebuilt one component at a time. Currently shipped:

- **Elements** — `Badge`, `BadgeGroup`, `Button`, `ButtonGroup`
- **Content** — `Figure`
- **Layout** — `Column`, `Section`
- **Template Parts** — `Article`, `Aside`, `Body`, `Main`
- **Utilities** — `LinkProvider`

Each component lives in its own folder under `src/components/` with co-located stories, styles,
docs, and types. See [the changelog](?path=/docs/overview-changelog--docs) for what's landed.

### WordPress integration

This is where the single-source-of-truth pipeline earns its keep.
`@troychaplin/component2block` outputs a `theme.json` and integration helper alongside the React
build, so the Site Editor, the block editor, and the front end all inherit the same tokens. The
pipeline produces:

- A `theme.json` defining the color palette, gradients, fluid typography, spacing scale, and shadow presets
- Per-block CSS that can be enqueued only when a block is used
- Editor styles so authors see the same token-driven design while they write

No hand-maintained WordPress stylesheet, and no drift between what a designer specced in React and
what an author sees in the editor.

### Accessibility tested

Every Storybook story runs through [axe](https://github.com/dequelabs/axe-core) at the `error`
threshold — a violation in any story fails CI. See the
[accessibility page](?path=/docs/overview-getting-started-accessibility--docs) for the approach.

## Design principles

- **Consistency** — one visual language across every surface the system ships to
- **Accessibility** — WCAG-aware components, automated axe checks on every story
- **Composability** — small, focused components that combine into complex interfaces
- **Token-first** — all visual values come from `--octave--*` custom properties; no hardcoded hex codes, font stacks, or pixel values

## Tech stack

- React 18 and 19, TypeScript 6
- Vite 8 library mode (ESM + CJS)
- SCSS + CSS custom properties (no Tailwind, no CSS-in-JS)
- Storybook 10 with `@storybook/react-vite`
- Vitest + Playwright for unit and a11y testing
