# About Octave

Octave is a React component library and design system — a token-driven set of accessible,
composable building blocks for web interfaces. It pairs a generated design-token pipeline with
components that consume those tokens exclusively, so the visual language stays consistent
wherever it ships.

## What's here today

Octave is **early-stage and being rebuilt**. The token pipeline, build system, and accessibility
tooling work; the component catalogue is small and growing. See
[Getting Started](?path=/docs/overview-getting-started-overview--docs) for installation.

### Design tokens

A single set of tokens drives both the React library and the WordPress block theme output. Tokens
are defined in `c2b.config.json` and generated by
[`@troychaplin/component2block`](https://www.npmjs.com/package/@troychaplin/component2block) into
CSS custom properties (`--octave--*`), SCSS variables, base element styles, and `theme.json`.

- **Colors** — primary (with dark variant), secondary, semantic states (success, warning, error, info), full neutral scale
- **Typography** — Inter typeface, fluid heading and body scales, four font weights, three line-height options
- **Spacing** — seven-step fluid scale from `2-x-small` to `2-x-large`
- **Effects** — shadow presets (natural, sharp, outlined), border radii, gradients
- **Layout** — content max-width, wide max-width

Browse the live token reference under **Stylebook** in the sidebar.

### Components

The catalogue is being rebuilt one component at a time. Currently shipped:

- **Elements** — `Badge`, `BadgeGroup`, `Button`, `ButtonGroup`
- **Content** — `Figure`
- **Layout** — `Section`
- **Template Parts** — `Article`, `Aside`, `Body`, `Main`

Each component lives in its own folder under `src/components/` with co-located stories, styles,
docs, and types. See [the changelog](?path=/docs/overview-changelog--docs) for what's landed.

### WordPress integration

`@troychaplin/component2block` outputs a `theme.json` and integration helper alongside the React
build, so the WordPress Site Editor and frontend stay in sync with the design system. The token
pipeline produces:

- A `theme.json` defining the color palette, gradients, fluid typography, spacing scale, and shadow presets
- Per-block CSS that can be enqueued only when a block is used
- Editor styles so authors see the same token-driven styles while editing

### Accessibility tested

Every Storybook story runs through [axe](https://github.com/dequelabs/axe-core) at the `error`
threshold — a violation in any story fails CI. See the
[accessibility page](?path=/docs/overview-getting-started-accessibility--docs) for the approach.

## Design principles

- **Consistency** — one visual language across every surface the system ships to
- **Accessibility** — WCAG-aware components, automated axe checks on every story
- **Composability** — small, focused components that combine into complex interfaces
- **Token-first** — all visual values come from `--octave--*` custom properties; no hardcoded hex codes, font stacks, or pixel values

## Tech stack

- React 18+, TypeScript 6
- Vite library mode (ESM + CJS)
- SCSS + CSS custom properties (no Tailwind, no CSS-in-JS)
- Storybook 10 with `@storybook/react-vite`
- Vitest + Playwright for unit and a11y testing
